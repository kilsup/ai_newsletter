AI Eng #01 ASD-STE100 • Process Upgrade 2026-11-26

AI가 뽑아준 장문의 답, 왜 읽다 지칠까? — 연구원의 '이해 프로세스' 4단계 전환

생각과 초안 작성은 에이전트에게 맡길 수 있다. 하지만 이해는 외주를 맡길 수 없다. 코드와 논문 생성이 빨라진 지금, 진짜 병목은 '읽고 내 것으로 만드는 속도'다.

BEFORE (지금 겪는 병목) "설명해 줘"라고 묻고 3페이지 장문을 읽는다. 매번 목차가 달라지고, 쉽게 줄이면 실무 디테일이 빠진다.
AFTER (바뀐 프로세스) 으로 압축하고, 클릭형 HTML로 구조를 보며, 고정 포맷 스킬로 모든 문서를 같은 틀로 읽는다.
01

일하다 보면 이런 문제가 생긴다

PAIN 01 • 장황함 vs 누락

길면 안 읽히고, 줄이면 알맹이가 빠진다

새 코드나 논문을 그냥 설명해 달라고 하면 3페이지 장문이 나온다. 반대로 쉽게 요약하라고 하면 실험 조건과 핵심 로직이 증발한다.

PAIN 02 • 줄글의 구조 한계

글만 읽어서는 흐름과 연결이 안 잡힌다

복잡한 저장소의 호출 순서나 멀티 모듈 구조는 줄글로 읽어도 머릿속에 그려지지 않는다. 결국 코드를 처음부터 다시 열어 본다.

PAIN 03 • 매번 바뀌는 형식

설계 문서 5개를 물으면 5개 다 목차가 다르다

에이전트는 비결정적(Non-deterministic)으로 답한다. 문서마다 출력 구조가 달라지면 독자는 매번 새 형식에 적응하느라 에너지를 낭비한다.

02

이렇게 바꾸면 이해 속도가 달라진다

기존의 수동 정독 흐름(상단)을 4단계 능동 프로세스(하단)로 전환한다. 하단 박스를 클릭해 단계별 전환 방법을 확인한다.

그림 1. 수동 장문 정독(Before)에서 능동·고정 포맷 이해(After)로의 워크플로우 전환

전환 1: 자유 서술을 버리고 '언어 규격'을 지정한다

기존 방식"설명해 줘"로 장문을 받거나, "쉽게 써줘"로 핵심 스펙을 잃는다.
바뀐 방식낯선 개념은 로 진입하고, 실무 분석은 ASD-STE100으로 압축한다.

항공 정비 규격인 ASD-STE100을 지시하면 에이전트는 불필요한 미사여구를 버린다. 문장은 짧아지고 구조·절차·원인 같은 기술 밀도는 유지된다.

전환 2: 줄글을 읽지 않고 '조작하는 HTML 1장'으로 바꾼다

기존 방식마크다운 텍스트를 스크롤하며 모듈 간 연결 관계를 머릿속으로 조합한다.
바뀐 방식다이어그램·표가 담긴 을 생성해 직접 클릭하며 탐색한다.

복잡한 저장소도 노드를 누르면 역할과 원문 파일 라인 번호가 즉시 뜬다. 버그 수정이나 요청 처리 시나리오를 버튼으로 재생하면 동작 흐름이 1분 안에 잡힌다.

전환 3: 읽고 끝내지 않고 '퀴즈·쇼츠'로 이해를 확정한다

기존 방식요약을 다 읽고 이해했다고 착각한 뒤, 다음 날 구현할 때 다시 헤맨다.
바뀐 방식에이전트에게 핵심 10~16문항 퀴즈를 출제하게 해 빈틈을 바로 찾는다.

부품과 역할을 연결하거나 예외 상황을 묻는 퀴즈를 풀면 모르는 지점이 즉시 드러난다. 이동 중 빠른 복습이 필요하면 핵심 흐름을 짧은 쇼츠 클립으로 뽑는다.

전환 4: 문서 유형별 '포맷 전용 스킬'로 틀을 고정한다

기존 방식PR·설계 문서·논문을 물을 때마다 매번 다른 구조로 답이 나와 다시 파악한다.
바뀐 방식만 정의한 경량 스킬(예: into)로 출력 형식을 통일한다.

설계 문서 5개를 읽어도 5개 모두 '한 줄 요약 → 문제 → 구조 → 트레이드오프' 순서로 나온다. 읽는 뇌의 전환 비용이 사라지고 다음 행동 결정이 빨라진다.

04

오늘 바로 복사해 쓰는 실행 플레이북

현재 쓰는 AI 에이전트(Claude Code, Cursor, ChatGPT 등)에 아래 문구를 그대로 붙여 넣어 차이를 확인한다.

플레이북 1. 장문을 끝내는 ASD-STE100 압축 프롬프트
  • 긴 코드 리뷰나 논문 설명이 필요할 때 질문 맨 끝에 아래 규칙을 붙인다.
ASD-STE100 원칙을 한국어에 적용해 설명해 줘.
1. 한 문장에 하나의 정보만 담고 18어절을 넘기지 마.
2. 능동태로 쓰고 행위 주체를 분명히 밝혀.
3. 모호한 형용사(매우, 혁신적인, 적절한 등) 대신 수치와 조건을 써.
4. [문제 → 전체 구조 → 단계별 동작 → 트레이드오프] 순서로 고정해.
플레이북 2. 낯선 코드·논문을 '클릭형 HTML 1장'으로 바꾸는 프롬프트
  • 저장소나 PDF를 분석할 때 텍스트 대신 바로 브라우저에서 열어볼 단일 HTML을 요청한다.
이 내용을 외부 라이브러리 없는 단일 인터랙티브 HTML 파일로 만들어 줘.
- 핵심 아키텍처와 데이터 흐름을 인라인 SVG 다이어그램으로 그려 줘.
- 각 노드를 클릭하면 역할, 입출력, 원문 출처(파일명·라인 번호 또는 논문 섹션)를 표시해 줘.
- 핵심 개념 이해 여부를 점검하는 5문항 객관식 퀴즈를 하단에 넣어 줘.
플레이북 3. 경량 포맷 스킬(into) 설치 및 커스터마이징
  • 12개 유형(PR, 설계 문서, 저장소, 논문, 커리큘럼 등) × 3단계 깊이 포맷이 담긴 경량 스킬을 설치해 우리 팀 형식으로 수정한다.
npx skills add jha0313/skills_repo --skill into
05

우리 팀에 응용할 프로세스 개선 아이디어 & 주의 사항

IDEA 01 • 이슈 분석 · 개선 · 검증 자동 리포트

이슈 처리가 끝나면 에이전트가 '이해 중심 완료 보고서'를 자동 생성한다

이슈 분석·수정·검증이 끝난 뒤 흩어진 주행 로그와 PR을 수동으로 정리하지 않는다. 작업 종료 시 고정 포맷 스킬을 호출해 리뷰어가 1분 안에 맥락을 파악할 보고서를 받는다.

적용 예제 — [이슈 #412 MPA 구간 Relocalization 실패 개선 리포트]
  • 원인 요약 (ASD-STE100): 지하주차장 반복 기둥 구간에서 Keypoint 오매칭이 늘어 Pose 오차가 0.8m를 초과한다. (출처: keypoint_matcher.cpp:L218)
  • 수정 전/후 흐름도 (SVG): 단순 디스크립터 매칭(Before)과 기하 검증·공시야 필터 추가(After)를 2단 블록으로 대비한다.
  • 검증 결과표: 재인식 성공률 78% → 96%, 평균 위치 오차 0.42m → 0.11m, 회귀 주행 로그 42/42 통과, 롤백 커밋 해시 자동 첨부.
IDEA 02 • 고객사 송부용 단일 HTML 분석 리포트

고객사 전달용 분석 결과를 '열어보면 바로 이해되는 HTML 1장'으로 분리 생성한다

내부 알고리즘 로그나 복잡한 CSV 대신 고객사 담당자가 별도 도구 없이 브라우저로 확인하는 전용 HTML 포맷을 둔다. 외부 CDN 없이 파일 1개로 완결해 메일이나 메신저에서도 깨지지 않는다.

적용 예제 — [고객사 송부용 MPA/MRA 주행 이슈 분석 리포트.html]
  • 상단 30초 요약: 내부 구현 용어를 빼고 시험 주행 중 경로 이탈 현상과 패치 결과를 3문장으로 제시한다.
  • 클릭형 주행 타임라인 SVG: 구간 진입 → 저조도 특징점 저하 → 보정 패치 적용 → 정상 추종 단계를 클릭해 구간별 수치만 확인한다.
  • 조건별 비교표 & 고객사 액션: 야간·역광·반복 패턴 조건별 성공률과 실차 재검증 체크리스트를 함께 제공한다.
IDEA 03 • 학습 단계별 맞춤 시각화 학습 팩

새 개념을 공부할 때 '현재 이해 단계'에 맞춘 시각 자료를 단계별로 받는다

차기 프로젝트의 새 아키텍처나 논문을 줄글로만 읽지 않는다. 입문·구조·심화 3단계에 맞춰 그림과 인터랙티브 요소를 점진적으로 확장해 이해 공백을 없앤다.

적용 예제 — [차기 과제: BEV 기반 Semantic SLAM & World Map 3단계 학습 팩]
  • 1단계 (입문 · 직관 확보): 기존 Keypoint V-SLAM과 BEV 입력(주차공간·객체·Freespace) 기반 Semantic SLAM의 차이를 1장 비교도로 3분 안에 잡는다.
  • 2단계 (구조 · 원리 파악): BEV 인식 입력 → 데이터 연관(Association) → World Map 갱신·관리 흐름을 클릭형 Step-through SVG와 비교표로 확인한다.
  • 3단계 (심화 · 실전 검증): 동적 객체 필터링·맵 경량화 트레이드오프 표 + 핵심 5문항 객관식 퀴즈로 설계 전 이해 누락을 점검한다.
도입 전 반드시 점검할 주의 사항 (Trade-offs)
  • 고객사 송부 전 민감 정보 마스킹 필수: 고객사용 HTML 자동 생성 시 내부 파일 경로, 사내 서버 주소, 미공개 코드가 본문이나 SVG 주석에 남지 않도록 전용 템플릿과 사전 검수 절차를 분리한다.
  • 이슈 보고서의 근거 링크 강제: 자동 보고서가 깔끔할수록 오류(Hallucination)를 놓치기 쉽다. 원인 설명과 검증 수치 옆에 실제 파일 라인 번호, 커밋 해시, 테스트 로그를 함께 출력하게 강제한다.
  • 단순 질문에 시각화 남용 금지: 3줄로 끝날 개념까지 단계별 HTML로 만들면 생성 대기 시간이 오히려 병목이 된다. 팀과 공유하거나 2번 이상 다시 볼 이슈·개념에만 시각화를 적용한다.

ASD-STE100

ELI5 (Explain Like I'm Five)
전문 용어를 빼고 일상 비유로 개념의 큰 그림을 먼저 잡도록 유도하는 프롬프트 기법.

문서 유형별 고정 출력 틀. 매번 같은 순서로 정보를 제공해 독자의 인지 전환 비용을 없앤다.
into 스킬 (into Skill)
